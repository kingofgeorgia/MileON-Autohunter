# 📚 Источники данных для обучения ML модели

## 🎯 Откуда брать данные?

ML модель обучается на **закрытых сделках** — реальных случаях покупки и продажи автомобилей. Для каждой сделки нужно знать:

1. **Цену покупки** — за сколько купили
2. **Цену продажи** — за сколько продали
3. **Время продажи** — сколько дней держали
4. **Стоимость ремонта** — сколько потратили на восстановление (опционально)

---

## 📊 Источник #1: Ваши реальные сделки

### Где взять данные:
- **Ваш бухгалтерский учет** — записи о покупке/продаже автомобилей
- **Договоры купли-продажи** — официальные документы
- **Учетные системы** — CRM, Excel таблицы, бухгалтерские программы
- **История банковских транзакций** — приходы/расходы на покупку и продажу

### Какая информация нужна:
```
Пример записи:
- Марка: Toyota
- Модель: Camry
- Год: 2018
- Пробег: 85,000 км
- Тип двигателя: бензин
- КПП: автомат
- Привод: передний
- Цена покупки: $12,000
- Цена продажи: $14,500
- Дней держали: 35
- Стоимость ремонта: $300
```

### Как добавить в базу:

#### Способ 1: Интерактивный скрипт (для единичных сделок)
```bash
python add_closed_deals.py
```
Выберите опцию 2 (добавить вручную) и введите данные.

#### Способ 2: CSV импорт (для массового добавления)
1. Создайте CSV файл `my_deals.csv`:
```csv

15,12000,14500,35,300
42,8500,9800,28,150
103,15000,17200,52,600
```

2. Запустите импорт:
```bash

```

**Важно:** `listing_id` — это ID автомобиля из вашей базы (`car_listings`). Чтобы найти его:

### Идея:

1. **Мониторить листинги** ежедневно

- Неизвестна реальная цена продажи (может быть ниже цены листинга)
- Неизвестно, был ли ремонт

## 📊 Источник #4: Генерация синтетических данных (не рекомендуется)

### Для начального тестирования:
Можно сгенерировать **тестовые данные** на основе средних рыночных значений:

```python
# Пример генерации тестовых данных
# НЕ ИСПОЛЬЗУЙТЕ для продакшена!

async def generate_test_deals(count: int = 50):
    """Генерация тестовых сделок для проверки ML."""
    import random
    
    async with async_session_maker() as session:
        # Получить случайные листинги
        listings = (await session.scalars(
            select(CarListing).limit(count)
        )).all()
        
        for listing in listings:
            purchase = listing.price_usd or 10000
            
            # Случайная прибыль 10-20%
            markup = random.uniform(1.10, 1.20)
            sell = purchase * markup
            
            # Случайное время держания 20-60 дней
            days = random.randint(20, 60)
            
            # Случайный ремонт 0-5% от покупки
            repair = purchase * random.uniform(0, 0.05)
            
            await add_deal(
                session, listing.id, purchase, sell, days, repair
            )
```

⚠️ **Не рекомендуется:** Синтетические данные не отражают реальный рынок!

## 🎯 Минимальные требования

### Для базовой модели:
- **50-100 сделок** — минимум для работы модели
- **R² ожидается:** 0.50-0.70 (средняя точность)
- **Использование:** Только отображение в GUI, не влияет на ROI

### Для хорошей модели:
- **200-500 сделок** — рекомендуется
- **R² ожидается:** 0.70-0.85 (хорошая точность)
- **Использование:** Влияет на расчет ROI и прибыли (если R² ≥ 0.75)

### Для отличной модели:
- **1000+ сделок** — идеально
- **R² ожидается:** 0.85-0.95 (высокая точность)
- **Использование:** Полная замена расчетных формул

## ⚠️ Важные замечания

### Качество данных:
- **Реальные сделки лучше синтетических** — всегда используйте свои данные
- **Чем больше, тем лучше** — 1000 сделок намного точнее 50
- **Разнообразие важно** — разные марки, годы, ценовые диапазоны

### Ограничения модели:
- ML не учитывает **экстремальные ситуации** (кризисы, дефицит)
- ML плохо работает на **редких авто** (мало данных для обучения)
- ML требует **актуальных данных** (не старше 1-2 лет)

### Конфиденциальность:
- Все данные хранятся **локально** (mileon_saas.db)
- Никуда не передаются
- Можно анонимизировать (удалить VIN, номера телефонов)

## 💡 FAQ

**Q: У меня только 10 сделок, можно ли обучить модель?**  
A: Технически да, но модель будет очень неточной (R² < 0.5). Дождитесь 50+ сделок.

**Q: Можно ли использовать данные с других рынков (США, Европа)?**  
A: Не рекомендуется — цены очень разные. Нужны данные вашего региона.

**Q: Как часто обновлять модель?**  
A: Раз в 3-6 месяцев или после 100+ новых сделок.

**Q: Модель показывает плохие прогнозы, что делать?**  
A: Добавьте больше данных и переобучите. Если R² < 0.75, модель не влияет на ROI.

**Q: Можно ли обучить модель на прогнозе времени продажи (days_held)?**  
A: Да! Измените `target_field="sell_price"` на `"days_held"` в train_ml_model.py.
