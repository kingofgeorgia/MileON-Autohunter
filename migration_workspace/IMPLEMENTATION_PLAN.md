# План переноса на backend/frontend

## 1. Цель
Создать новую архитектуру проекта в отдельной рабочей папке, где:
- backend будет запускаться на Windows;
- frontend будет разворачиваться как отдельное веб-приложение и открываться с любого устройства;
- сначала будет работать без авторизации, затем добавятся авторизация и тарифная сетка.

## 2. Основная структура
- backend/ — API на FastAPI или другой подходящий стек для Windows
- frontend/ — отдельное приложение для UI, лучше как отдельный веб-проект
- shared/ — общие схемы, типы и правила расчётов
- docs/ — спецификации и заметки

## 3. Выбор frontend-структуры
Рекомендуется сделать frontend отдельным веб-приложением, а не одной страницей внутри backend.

Почему так лучше:
- frontend можно разворачивать независимо;
- удобно запускать и тестировать на любой машине;
- проще потом добавить авторизацию, админку и мобильную версию;
- backend останется чистым API-сервисом.

Рекомендация:
- для MVP использовать отдельное приложение на Next.js или Vite;
- если нужен быстрый старт — сначала сделать отдельную веб-страницу с современным UI, затем перейти в полноценное приложение.

## 4. UI/UX-подход
На первом этапе UI должен быть:
- простым и понятным;
- быстрым в использовании;
- адаптивным для десктопа и мобильных устройств;
- визуально современным, с понятной иерархией блоков.

Что внедрить:
- светлую и тёмную тему;
- карточки с ключевыми показателями;
- понятные фильтры и шаги расчёта;
- визуализацию итоговой стоимости;
- прогресс-steps для расчёта;
- понятные состояния загрузки и ошибок.

## 5. Этапы разработки
### Этап 1 — подготовка ядра
- создать базовую структуру backend/frontend/shared;
- сделать hello-world API и стартовую страницу frontend;
- подготовить базовый маршрут для расчёта.

### Этап 2 — расчёт стоимости
- реализовать расчёт стоимости ввоза и растаможки;
- сравнивать результаты с Alta.ru как ориентиром;
- сделать конфигурируемые ставки, логистику, брокерские и таможенные расходы;
- реализовать расчёт через ссылку на объявление myauto.ge.

### Этап 3 — MVP без авторизации
- ввести форму ввода данных автомобиля;
- показывать итоговую стоимость;
- показывать выгодность сделки;
- сохранить базовый поток расчёта без пользователей.

### Этап 4 — авторизация
- добавить вход и регистрацию;
- разделить данные по пользователям;
- затем добавить роли и права доступа.

### Этап 5 — тарифная сетка
- добавить тарифы для клиентов;
- сделать возможность управлять тарифами из интерфейса;
- связать стоимость расчётов с тарифами.

## 6. Расчёт стоимости
Особое внимание уделить точности.

Требования:
- расчёт должен быть близок к реальным таможенным и логистическим затратам;
- результаты желательно сравнивать с Alta.ru как эталоном по структуре калькуляции;
- в дальнейшем можно ввести дополнительные поправочные коэффициенты, если реальные расхождения будут заметны.

Что нужно учесть:
- стоимость автомобиля;
- логистику до РФ;
- таможенные платежи;
- брокерские услуги;
- оформление документов;
- дополнительные расходы и комиссии;
- валютные курсы и обновляемые ставки.

## 7. Расчёт через ссылку myauto.ge
Нужно реализовать функцию, которая:
- принимает ссылку на объявление myauto.ge;
- извлекает основные параметры автомобиля;
- подставляет их в расчёт;
- возвращает итоговую стоимость растаможки и ввоза.

## 8. Следующий шаг
Сначала реализовать:
1. базовую структуру backend/frontend/shared;
2. стартовый расчёт стоимости;
3. MVP-страницу с красивым интерфейсом;
4. затем добавить авторизацию и тарифы.
